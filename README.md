# Зикр

Счётчик зикров, времена намаза, кибла и календарь по хиджре. Одно приложение,
которое открывается с экрана «Домой» и целиком работает без интернета.

**Открыть: https://artmartiros.github.io/zikr/**

На айфоне: Safari → «Поделиться» → «На экран „Домой“». Дальше адресной строки
не будет, а сеть не понадобится вовсе.

## Что внутри

| Экран | Что делает |
|---|---|
| **Зикр** | Счётчик на весь экран: десять готовых наборов и свой. Тасбих после намаза идёт последовательностью 33 · 33 · 34 и сам переходит с фразы на фразу |
| **Намаз** | Времена пяти намазов на сегодня, отметка прочитанного, ближайший намаз с обратным отсчётом, кибла и дата по хиджре |
| **Прогресс** | Серия дней подряд, дневная цель, две недели зикров, неделя намазов, итоги по наборам |

Кольцо счётчика при цели до сорока превращается в настоящие чётки — одна
бусина на одно произнесение. Дальше зерно стало бы кашей, и прогресс рисуется
дугой.

## Ничего не уходит наружу

Ни аккаунта, ни сервера, ни единого сетевого запроса после первой загрузки.
Времена намаза и кибла считаются на самом устройстве по координатам и
положению Солнца, история лежит в localStorage браузера. Поэтому приложение
одинаково работает в самолёте, в подвале и в поездке без роуминга.

Тактильный отклик на iPhone сделан обходным путём: Vibration API в Safari нет
и не будет, зато iOS 17.4 научилась рисовать `<input type="checkbox" switch>`,
и переключение такого чекбокса даёт системный отклик в палец.

## Железное правило

Ни одна сборка не едет без проверок, и это не обещание, а ворота в CI:

```
npm run check
```

```
node check/counter.mjs       # счётчик не теряет произнесения на быстром зикре
node check/prayer-times.mjs  # восход и закат против реальности, порядок намазов, полярные широты
node check/hijri.mjs         # опорные даты, объявленные публично, и непрерывность за три года
node check/qibla.mjs         # азимуты сверены с известными для шести городов
node check/dhikr.mjs         # арабский текст, транслитерация, часовые пояса всех городов
```

Проверки не декоративные — каждая стоит на уже совершённой ошибке:

* **Счётчик** брал текущий счёт из замыкания рендера. При спокойном темпе всё
  сходилось, а на быстром зикре React не успевал перерисоваться между
  нажатиями — и девятнадцать тапов давали единицу. На экране это выглядит не
  как ошибка, а как «телефон подтормаживает».
* **Юлианский день** считался с `Math.floor` там, где формула написана под
  усечение к нулю. Дата по хиджре уезжала на двое суток и выглядела при этом
  совершенно правдоподобно.
* **Полярные широты** возвращали NaN: в Мурманске в июне солнце не садится, и
  восхода с закатом нет физически. Теперь работает «акраб аль-биляд» —
  расписание ближайшей местности, где сутки ещё делятся на день и ночь.
* **Латинская `h`** пролезла в кириллическую транслитерацию «ли-Лляh». Глазом
  не видно, а шрифт подставляет другой начерк.

## Расчёты

Положение Солнца — по упрощённым формулам NOAA, дальше часовой угол для нужной
высоты. Восход и закат сходятся с реальностью до минуты: Москва 21 июня —
03:44 и 21:17, Лондон — 04:43 и 21:21.

Методов расчёта семь (Всемирная лига, СМР, Умм аль-Кура, Египет, Карачи, ISNA,
Диянет), углы фаджра и иши подписаны прямо в настройках. Аср считается по обеим
школам. Летом севернее Москвы астрономических фаджра и иши просто нет — тогда
ночь делится по выбранному правилу, а время помечается знаком `≈`, чтобы никто
не принял оценку за астрономию.

Дата по хиджре берётся из календаря `islamic-umalqura`, встроенного в сам
браузер: он совпадает с саудовским день в день. Табличный алгоритм остался
запасным вариантом. Сутки по хиджре начинаются с закатом, поэтому после магриба
дата уже следующая.

## Разработка

```
npm install
npm run dev
```

```
npm run icons   # растровые иконки из public/icon.svg
npm run build   # сборка вместе с service worker
```

Service worker пишется плагином сборки, а не руками: список файлов для
предзагрузки должен содержать реальные имена бандлов с хешами. Набитый вручную
список разошёлся бы с первым же билдом, и офлайн тихо перестал бы работать —
тихо, потому что на компьютере разработчика сеть есть всегда.
